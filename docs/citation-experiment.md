# Citation Experiment — Stage 3A: можно ли научить 3B-модель цитировать?

## 1. Вопрос и гипотеза

Локальная Llama-3.2-3B (Q4_K_M, llama.cpp, CPU) стабильно даёт фактически
корректные ответы без цитат: 10/12 на dev-наборе при correctness 100%
(см. docs/answer-quality-evaluation.md). Продовый prompt содержит только
правило «Ссылайся на источники в формате [1], [2]» — без примера формата.

Гипотеза: явный few-shot пример формата + жёсткое требование цитирования
повысят citation coverage **без** деградации correctness и abstention.

## 2. Методология

- Скрипт: `backend/benchmarks/citation_experiment.py`. Production
  `app/core/rag.py` не меняется; V0 — точная копия `SYSTEM_PROMPTS`
  (закреплено тестом `test_v0_is_exact_production_prompt`).
- Модель: llama.cpp b11826, Q4_K_M (bartowski), CPU `-ngl 0`, ctx 4096,
  temperature 0.2, max_tokens 256.
- Набор: dev `golden_answers.json` (12 answer + 5 negative). Retrieval/context
  строится **один раз на вопрос** — идентичен для всех вариантов.
- Протокол: чистый индекс пересобирается с нуля на старте (первая версия
  эксперимента попала на загрязнённый корпус и была аннулирована — §6).
- Оценка: те же детерминированные `check_*` функции, что в answer_eval
  (без дублирования); знаменатели публикуются явно.
- Выбор кандидата (`select_candidate`, порядок важен):
  1. correctness не хуже V0;
  2. refusal_pass_rate не хуже V0;
  3. citation_validity не хуже V0 (формальные/неверные цитаты);
  4. среди прошедших — строго больше coverage, чем у V0;
  5. при равенстве — минимальный вариант (V0 приоритетен).
- Held-out (`golden_answers_v2.json`, 8+3) — только финальный прогон V0 +
  выбранного кандидата, без выбора по нему. **Предварительно: выборка мала.**

## 3. Варианты промпта

| Вариант | Содержимое |
|---|---|
| V0 | production prompt как есть |
| V1 | V0 + few-shot пример ответа с `[1]`/`[2]` (вымышленный домен «командировки», факты не из набора — закреплено тестом) |
| V2 | V1 + правила: каждое фактическое утверждение — с `[n]`; неприводимые утверждения не включать; ответ с фактами без `[n]` неполный |

Полные тексты — в артефакте `results/*citation_experiment*.json` (`prompts`).

## 4. Результаты (dev)

### Dev-набор (12 answer + 5 negative, 2026-11-03, валидный прогон `20261103_184117`)

| Метрика (знаменатель) | V0 | V1 | V2 |
|---|---|---|---|
| Answer correctness (12) | 92% (11/12) | 92% (11/12) | 92% (11/12) |
| Incorrect answers (12) | 1 | 1 | 1 |
| **Citation coverage** (12) | 2/12 (17%) | 1/12 (8%) | **5/12 (42%)** |
| Citation precision (только цитирующие ответы) | 1.0 (n=2) | 1.0 (n=1) | 1.0 (n=5) |
| Citation validity (12) | 0.167 | 0.083 ↓ | 0.417 |
| Correct без цитат (12) | 9 | 11 | 7 |
| Refusal correctness (5) | 100% | 100% | 100% |
| out tokens, среднее | 43.2 | 42.1 | 41.2 |

- V1 (только few-shot) coverage **не поднял** (1/12) и деградировал по citation
  validity — few-shot пример сам по себе 3B-модель не переносит в собственные ответы.
- V2 (few-shot + явные правила) поднял coverage 2→5 при неизменном correctness,
  refusal и precision 1.0 (все 5 цитат ведут на целевой документ — «формальных»
  цитат не появилось).
- Один incorrect общий у всех трёх (a11, двухчастный вопрос: V2 назвал скидку
  НКО 30%, но неверно привязал её к «тарифу Корпоративный» и не назвал 9990) —
  деградация на многосоставном вопросе, не связана с цитированием.

### Held-out v2 (8 answer + 3 negative, `20261103_184530`) — ПРЕДВАРИТЕЛЬНО

| Метрика (знаменатель) | V0 | V2 (кандидат) |
|---|---|---|
| Answer correctness (8) | 75% (6/8) | 75% (6/8) |
| Citation coverage (8) | 3/8 (38%) | **4/8 (50%)** |
| Citation precision (цитирующие) | 1.0 (n=3) | 1.0 (n=4) |
| Refusal correctness (3) | 100% | 100% |

Направление dev-результата воспроизводится (+1 цитирующий ответ, precision 1.0,
качество не изменилось), но разница — **1 ответ**: на выборке 8+3 вывод
предварительный, статистической силы нет.

## 5. Примеры ответов

**До (V0, вопрос a2 — компенсация за интернет):**
> Компания компенсирует до 3000 руб./мес. на интернет.

Факт верный, citation coverage = 0 — ссылка [1] отсутствует.

**После (V2, вопрос a4 — тариф Бизнес):**
> Цена тарифа Бизнес составляет 2990 руб/мес, а количество пользователей,
> включенных в этот тариф, равно 25 [1], [2].

Факты верные, обе ссылки ведут на целевой документ (precision 1.0).

**Отказ (V2, negative n6 — Training-курсы):**
> В предоставленных документах информации об оплачиваемых компанией
> Training-курсах нет. В контексте содержатся только: Политика удалённой
> работы … [1], [4]

Честный отказ: ни одного выдуманного факта, цитаты — на перечисление «что есть
вместо» (легитимно по правилам отказа).

## 6. Инцидент протокола: первый прогон аннулирован

Первая версия эксперимента стартовала на индексе с 20 lorem-чанками
(остаток robustness-эксперимента): контекст не содержал целевых фактов,
модель отвечала отказами и галлюцинациями («correctness 0%» против 100% на
чистом корпусе). Артефакт помечен `status: invalidated_polluted_index`
(сырые данные сохранены), протокол дополнен обязательной пересборкой индекса.
Урок: любой answer-эксперимент обязан проверять/строить корпус явно —
состояние индекса — часть конфигурации эксперимента.

## 7. Ограничения

- Модель на машине с глубоким swap: **latency/timings невалидны** и не
  используются для выбора prompt (сохранены в артефакте для полноты).
- Выборка мала (12+5 dev, 8+3 held-out) — разница 2–3 ответа не статистична.
- Judge не участвует в выборе (детерминированные проверки первичны).
- Один seed (temperature 0.2) на вариант — вариативность генерации не оценена.

## 8. Файлы и тесты

- `backend/benchmarks/citation_experiment.py` — эксперимент (V0/V1/V2, выбор кандидата, heldout-режим).

## 9. Рекомендация по переносу в production

**Рекомендация: переносить частично и условно.**

1. **Перенести V2 в production prompt для локальных моделей** (ветка
   Ollama/llama.cpp провайдера приложения): исправляет измеренный дефект
   (coverage 17%→42% dev, 38%→50% held-out) при неизменных correctness,
   refusal и precision 1.0; риски ограничены добавочными строками system
   prompt (~100 токенов overhead на запрос, в своп-окружении не измерялся).
2. **Не переносить для облачных моделей без нужды**: GLM-5.3-flash и так даёт
   coverage 100% на held-out — V2-требования ей не нужны.
3. **Условие переноса**: подтвердить на расширенном наборе (held-out ≥20
   answer-вопросов) — текущая разница держится на 3 ответах dev + 1 ответе
   held-out; и контролировать correctness при переносе (регрессионный гейт
   `compare.py --fail-on-regression`).
4. Few-shot без явных правил (V1) **не переносить**: измеренной пользы нет.
